Inheritance and Polymorphism

Why This Topic Matters

In an earlier post on classes and objects, we built classes that stood completely on their own. But in real programs, many classes are closely related to each other. A Dog and a Cat are both kinds of Animal. A card payment and a UPI payment are both kinds of Payment. Inheritance lets you write the shared parts once, and polymorphism lets you treat all these related objects the same way, even though each one behaves a little differently underneath.

By the end of this post you will know:

  1. How one class can inherit from another
  2. How to override and extend a parent's method with super()
  3. What polymorphism means in practice
  4. How multiple inheritance and the method resolution order work
  5. How to write a simple "must implement this" method

1. Inheritance

Inheritance lets a new class reuse the code that is already written in another class. The new class only needs to add or change the parts that are different.
class Animal:
    def __init__(self, name):
        self.name = name

    def speak(self):
        return f"{self.name} makes a sound"

class Dog(Animal):
    def speak(self):
        return f"{self.name} says Woof"

class Cat(Animal):
    pass

a = Animal("Generic")
d = Dog("Rex")
c = Cat("Whiskers")

print(a.speak())    # Generic makes a sound
print(d.speak())    # Rex says Woof
print(c.speak())    # Whiskers makes a sound

Writing class Dog(Animal): means Dog inherits from Animal. Animal is called the parent class, and Dog and Cat are its child classes. Cat did not write its own speak() method, so it simply borrows Animal's version. Dog wrote its own speak() method, so it uses that one instead. This is called overriding.

super(): Reusing the Parent's Code

Sometimes you do not want to fully replace the parent's method, you just want to add a little extra to it. super() lets a child class call the parent's own version of a method:

class Employee(Animal):
    def __init__(self, name, salary):
        super().__init__(name)     # reuse Animal's __init__
        self.salary = salary

    def speak(self):
        base = super().speak()     # reuse Animal's speak()
        return base + f", earns {self.salary}"

e = Employee("Bob", 50000)
print(e.speak())    # Bob makes a sound, earns 50000

This example is a bit unusual (an employee is not really an animal), but it shows how super() works clearly. super().__init__(name) ran the parent's own setup code for us, so we did not have to write self.name = name a second time.

Checking Types with isinstance()

print(isinstance(d, Animal))    # True, a Dog is also an Animal
print(isinstance(d, Dog))       # True
print(isinstance(a, Dog))       # False, a plain Animal is not a Dog

print(type(d).__name__)         # Dog

2. Polymorphism

Polymorphism means different classes can answer the same method call, each in its own way.

The word "poly" means many, and "morph" means form. So polymorphism just means "many forms of the same action."

class Shape:
    def area(self):
        return 0

class Circle(Shape):
    def __init__(self, r):
        self.r = r
    def area(self):
        return 3.14159 * self.r ** 2

class Square(Shape):
    def __init__(self, s):
        self.s = s
    def area(self):
        return self.s ** 2

shapes = [Circle(3), Square(4)]

for shape in shapes:
    print(type(shape).__name__, shape.area())

# Circle 28.27431
# Square 16

The loop calls shape.area() without needing to know whether shape is a Circle or a Square. Each object already knows how to work out its own area. This is the real benefit of inheritance, one piece of code can work with many different types.

def print_area(shape):
    print(f"Area: {shape.area()}")

for shape in shapes:
    print_area(shape)

# Area: 28.27431
# Area: 16

Notice that print_area() did not need any if statement to check what kind of shape it got. If you add a new shape class later, like Triangle, print_area() will still work with no changes at all, as long as Triangle also has an area() method.

Making Sure a Subclass Writes Its Own Method

Sometimes a parent class should never be used directly, it only exists so other classes can inherit from it. We can make Python show a clear error if someone tries, by raising NotImplementedError:

class Payment:
    def pay(self, amount):
        raise NotImplementedError("Subclass must implement pay()")

class CardPayment(Payment):
    def pay(self, amount):
        return f"Paid {amount} by card"

print(CardPayment().pay(100))    # Paid 100 by card

Payment().pay(100)
NotImplementedError: Subclass must implement pay()

This does not stop anyone from writing the code, but it fails with a clear message the moment someone tries to use Payment directly, instead of one of its subclasses.

3. Multiple Inheritance

A class can inherit from more than one parent at once:

class Flyer:
    def fly(self):
        return "I can fly"

class Swimmer:
    def swim(self):
        return "I can swim"

class Duck(Flyer, Swimmer):
    pass

d = Duck()
print(d.fly())     # I can fly
print(d.swim())    # I can swim

Which Parent Wins? The Method Resolution Order

What if two parent classes have a method with the same name? Python needs a rule to decide which one to use. It looks at the parents from left to right, in the order you wrote them:

class A:
    def greet(self):
        return "Hello from A"

class B:
    def greet(self):
        return "Hello from B"

class C(A, B):
    pass

print(C().greet())    # Hello from A, since A is listed first

You can see this search order for yourself with __mro__:

print(Duck.__mro__)
# (<class 'Duck'>, <class 'Flyer'>, <class 'Swimmer'>, <class 'object'>)

Multiple inheritance is a useful tool, but it can get confusing if the parent classes have a lot of overlap. It works best for small, simple abilities, like Flyer and Swimmer, rather than big, complicated parent classes.

Practice Questions

  1. What does it mean for a child class to "override" a method?
  2. What does super().__init__() do?
  3. In class C(A, B):, if both A and B define greet(), which one runs when you call C().greet()?
  4. Why is polymorphism useful in the shapes example, instead of writing separate functions for each shape?

Answers

  1. The child class defines its own version of a method that already exists in the parent, and that version is used instead.
  2. It runs the parent class's own __init__, so the child does not need to repeat that setup code.
  3. A's version, since Python searches parents left to right in the order they are listed.
  4. One function, like print_area(), works for every shape, current and future, as long as each has its own area() method, no extra if checks are needed.
