Classes and Objects

Why This Topic Matters

Earlier, when we needed to store a student's name and marks together, we used a dictionary: {"name": "A", "marks": [80, 90]}. This works, but it has a problem. As you write more code, you will use this same shape again and again. It is easy to spell a key wrong, or forget to add one, and Python will not warn you.

Object-oriented programming (OOP) gives us a better way. It lets us create our own custom type, one that holds both the data and the actions that work on that data, together in one place. In this post, you will learn:

  1. What a class is, and what an object is, one at a time
  2. Why we need a constructor, and what problem it solves
  3. The difference between data that belongs to one object, and data shared by all
  4. When to use a class instead of a dictionary
  5. The four big ideas that OOP is built on

1. What is a Class?

A class is a plan. It describes what something will look like and what it can do, without actually being a real thing itself.

Think of a class like an architect's drawing of a house, or a cookie cutter. The drawing shows where the rooms and doors go, but you cannot live inside a drawing. It only becomes a real house once someone builds it.

class Student:
    pass

This is a complete, working class. It does nothing yet, and it holds no data. It simply tells Python "there is a new type of thing called Student." We have only described the shape, we have not made anything real yet.

2. What is an Object?

An object is one real thing made from a class. Making an object from a class is called instantiation.

Going back to our house example, an object is the actual house built from the drawing, the one with a real address, that you can walk into. You can build many houses from the same drawing, and each one is separate from the others:

s1 = Student()
s2 = Student()

print(type(s1))    # <class '__main__.Student'>
print(s1 is s2)    # False, two separate objects

Student() is how we make an object. s1 and s2 are both objects of the Student class. Objects are also called instances. Even though they come from the same class, they are two different objects, so changing one will not affect the other.

3. A Class Without a Constructor

Right now, our Student class holds no data. We can still add data to one object, from outside the class:

class Student:
    pass

s1 = Student()
s1.name = "Satyam"
s1.age = 25

print(s1.name, s1.age)    # Satyam 25

This works, and it shows something useful: an object is really just a container that can hold pieces of data. We call these pieces attributes. But this way of adding data has a real problem. Nothing forces every Student to have a name and an age:

s2 = Student()
print(s2.name)
AttributeError: 'Student' object has no attribute 'name'

s2 was made without any errors, but forgetting to set its name causes a crash later, maybe far away from where the mistake actually happened, inside some other function that expected every Student to already have a name. A constructor fixes exactly this problem.

4. The Constructor: __init__

A constructor is a special method that runs by itself every time a new object is made. It is where you set up the object's starting data.

In Python, the constructor always has the name __init__:

class Student2:
    def __init__(self, name, age):
        self.name = name
        self.age = age

s3 = Student2("Anita", 30)
print(s3.name, s3.age)    # Anita 30

Now it is not possible to make a Student2 without giving it a name and an age. Python simply will not allow it:

s4 = Student2()
TypeError: Student2.__init__() missing 2 required positional arguments: 'name' and 'age'

This is the constructor doing its job. It makes sure every object starts out complete, with nothing missing. self stands for the specific object being made. It is always the first thing written inside any method in a class, and Python fills it in for you automatically, you never type it yourself when you call Student2("Anita", 30).

5. Giving an Object Its Own Actions

A class can also hold functions, called methods, that use the object's own data. The data (name, marks) and the action that uses it (average()) sit together in one place:

class Student3:
    def __init__(self, name, marks):
        self.name = name
        self.marks = marks

    def average(self):
        return sum(self.marks) / len(self.marks)

    def describe(self):
        return f"{self.name} scored an average of {self.average()}"

s5 = Student3("Satyam", [80, 90, 70])
print(s5.average())      # 80.0
print(s5.describe())     # Satyam scored an average of 80.0

Notice how describe() calls self.average(), so one method can use another method on the same object. Each object still keeps its own data separate from every other object:

s6 = Student3("Anita", [60, 70, 80])
print(s5.name, s6.name)    # Satyam Anita

Whoever calls s5.describe() does not need to know how the average gets calculated. They just call the method and get an answer back.

6. Data That Belongs to One Object, and Data Shared by All

An instance variable belongs to one single object. A class variable is shared by every object made from that class.

self.name and self.marks above are instance variables, each student keeps their own copy. A class variable is written directly inside the class, but not inside any method:

class Counter:
    count = 0     # class variable, shared by all objects

    def __init__(self):
        Counter.count += 1

c1 = Counter()
c2 = Counter()
c3 = Counter()

print(Counter.count)    # 3

Every time a new Counter gets made, the shared count goes up by one. This is useful for things that belong to the class as a whole, like keeping track of how many objects have been created so far.

7. A Practical Example: A Simple Bank Account

class BankAccount:
    def __init__(self, owner, balance=0):
        self.owner = owner
        self.balance = balance

    def deposit(self, amount):
        self.balance += amount

    def withdraw(self, amount):
        if amount > self.balance:
            raise ValueError("Insufficient funds")
        self.balance -= amount

acc = BankAccount("Satyam", 1000)
acc.deposit(500)
acc.withdraw(200)
print(acc.balance)    # 1300

Each account object keeps its own balance. The rules for deposit and withdraw sit right next to the data they work on, instead of being spread across separate, disconnected functions. The constructor makes sure every BankAccount starts out with a real owner and balance.

8. dict or Class: Which One Should You Use?

SituationUse
Simple, one-off data with no actions attached to itdict
You use the same kind of data, in the same shape, in many placesclass
You need to check, calculate, or enforce a rule on the dataclass
You want a few related types that share some behaviour but differ in othersclass, with one class building on another

9. The Four Big Ideas Behind OOP

Now that you have seen a class, an object, a constructor, and a method with your own eyes, here are the four ideas that all of object-oriented programming is really built on. You have actually already seen two of them at work above:

IdeaIn simple words
EncapsulationKeep the data and the actions that use it together, in one place, like Student3 keeping marks and average() together
AbstractionHide the messy details, and give people a simple way to use something, like calling s5.describe() without knowing how the average is worked out
InheritanceLet one class reuse the code already written in another class
PolymorphismLet different classes respond to the same instruction in their own way

The next two ideas, inheritance and polymorphism, need a second class to make sense, so they get their own detailed post.

Common Mistakes

MistakeWhat happensFix
Forgetting to write self as the first thing in a methodTypeError about argumentsself must always come first in every method
Using a class variable when you meant one object's own variableThe value is shared, and changes for every object at onceSet it as self.x = ... inside __init__ instead
Adding data directly, like s1.name = "A", instead of using a constructorEasy to forget a field on some objects, causing an AttributeError laterSet every field inside __init__, so it is required, not optional

Practice Questions

  1. What is the difference between a class and an object?
  2. What problem does a constructor solve, that a class without one does not?
  3. What does self stand for inside a method?
  4. What is the difference between a class variable and an instance variable?
  5. Which two of the four big ideas did you already see at work in this post?

Answers

  1. A class is the plan, a description with no real object yet. An object is one specific thing made from that plan.
  2. It makes sure every object starts out complete, with all its needed data set, instead of allowing objects that are missing something.
  3. The specific object the method is currently being used on.
  4. A class variable is shared by every object of that class. An instance variable belongs to only one object.
  5. Encapsulation, keeping data and actions together, and abstraction, hiding how a method works behind one simple call.
