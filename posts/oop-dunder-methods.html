Special (Dunder) Methods

Why This Topic Matters

Try printing one of our earlier objects directly, like print(acc) from the bank account example. You will get something unreadable like <__main__.BankAccount object at 0x7f...>. Try comparing two objects that hold the same data with ==, and you will get False, even though they look the same. Dunder methods (short for "double underscore methods") are how we teach our own classes to work naturally with Python's built-in tools, print(), ==, +, len(), sorting, and more.

By the end of this post you will know:

  1. What a dunder method is, and why __init__ was one all along
  2. __str__ and __repr__, controlling how an object displays
  3. __eq__ and __lt__, controlling comparison and sorting
  4. __add__, letting + work on your own objects
  5. __len__, letting len() work on your own objects

1. What is a Dunder Method?

A dunder method has double underscores on both sides, like __init__ or __str__. It connects your class to some built-in Python behaviour.

You have actually already used one in every class so far. __init__ is a dunder method, and Python calls it automatically whenever you create a new object. This post looks at a few more common ones.

2. __str__: Controlling How an Object Prints

class Point:
    def __init__(self, x, y):
        self.x = x
        self.y = y

    def __str__(self):
        return f"Point({self.x}, {self.y})"

p1 = Point(1, 2)
print(p1)    # Point(1, 2)

Without __str__, print(p1) would show something unreadable like <__main__.Point object at 0x...>. Python calls __str__ by itself, any time an object needs to be shown as text, like inside print() or an f-string.

__repr__: A Version Mainly Meant for Developers

__repr__ is closely related to __str__. It is meant to be a clear, exact description, mainly useful while debugging, and Python uses it as a backup whenever __str__ is missing:

class Point2:
    def __init__(self, x, y):
        self.x = x
        self.y = y

    def __repr__(self):
        return f"Point2(x={self.x}, y={self.y})"

p2 = Point2(1, 2)
print(p2)         # Point2(x=1, y=2)   , __repr__ used since __str__ is missing
print([p2])       # [Point2(x=1, y=2)] , lists always use __repr__ for their items

A simple rule that works well: write __repr__ so it shows something you could copy and paste back into Python to rebuild the object. Only add a separate __str__ if you also want a friendlier, easier-to-read version for print().

3. __eq__ and __lt__: Comparing Objects

class Vector:
    def __init__(self, x, y):
        self.x = x
        self.y = y

    def __repr__(self):
        return f"Vector({self.x}, {self.y})"

    def __eq__(self, other):
        return self.x == other.x and self.y == other.y

    def __lt__(self, other):
        return (self.x ** 2 + self.y ** 2) < (other.x ** 2 + other.y ** 2)

v1 = Vector(1, 2)
v2 = Vector(3, 4)

print(v1 == v2)    # False
print(v1 == Vector(1, 2))    # True, same x and y

Without __eq__, == would only check whether the two objects are the exact same one in memory. So even two vectors with the same x and y would still come back False. __lt__ tells Python what "smaller than" means for your object, here we decided a shorter vector counts as smaller:

print(v1 < v2)               # True, since 1**2+2**2 < 3**2+4**2

print(sorted([v2, v1]))
# [Vector(1, 2), Vector(3, 4)]

Once __lt__ is written, Python's built-in sorted() just works on your objects, the same way it already worked on numbers and strings.

4. __add__: Letting + Work on Your Objects

class Vector2:
    def __init__(self, x, y):
        self.x = x
        self.y = y

    def __add__(self, other):
        return Vector2(self.x + other.x, self.y + other.y)

    def __repr__(self):
        return f"Vector2({self.x}, {self.y})"

a = Vector2(1, 2)
b = Vector2(3, 4)

print(a + b)    # Vector2(4, 6)

Behind the scenes, a + b is really calling a.__add__(b). This is exactly how Python's own numbers work too, 3 + 4 is secretly (3).__add__(4), we just never had to think about it before now.

5. __len__: Letting len() Work on Your Objects

class Playlist:
    def __init__(self, songs):
        self.songs = songs

    def __len__(self):
        return len(self.songs)

p = Playlist(["Song A", "Song B", "Song C"])
print(len(p))    # 3

len(p) quietly calls p.__len__() for us. This lets your own object be used anywhere Python expects something with a length, which is useful if your object is later passed into code that was originally written for lists or other built-in collections.

Common Mistakes

MistakeWhat happensFix
Comparing two objects with == without defining __eq__Always False, even with the same valuesDefine __eq__ if you need value comparison
Calling sorted() on custom objects without __lt__TypeError, objects cannot be comparedDefine __lt__ to say how two objects should be ordered
Defining __str__ to return something other than a stringTypeError__str__ and __repr__ must always return a string
Printing an object without __str__ or __repr__An unreadable memory address is shownDefine at least one of them to control how it prints

With classes, inheritance, encapsulation and dunder methods, you now have the basic toolkit of object-oriented Python. These are the same ideas that pandas' DataFrame, and scikit-learn's model.fit() style, are built on underneath.

Practice Questions

  1. What is the difference between __str__ and __repr__?
  2. What method does Python call behind the scenes for a + b?
  3. Why does sorted() fail on a list of custom objects with no __lt__ defined?
  4. What does defining __len__ let you do with your object?

Answers

  1. __str__ is meant to be a friendly, readable display. __repr__ is meant to be unambiguous and debug-focused, and is used as a fallback, and always used inside lists.
  2. a.__add__(b)
  3. Python does not know how to decide which of two custom objects is "smaller", so it cannot put them in order without a defined __lt__.
  4. Use it with Python's built-in len() function, just like you would with a list or a string.
